# Интеграции Leasing Compass — Lab 2.5

## Состояние
Публичный GitHub Pages — только синтетический интерфейс. Не хранить в нём ключи, паспортные данные, токены, кредитные отчёты или реальные документы. Согласия в кабинете — учебные. Тестовые ответы не являются скорингом или одобрением.
Фактический провайдер БКИ, действующая CRM, договор пользователя кредитной истории, схема идентификации и тип электронной подписи партнёра пока не предоставлены. Ни один внешний API не считается подключённым.

## Целевая схема
Браузер -> российский HTTPS-сервер/BFF -> сервер приложений -> PostgreSQL (РФ) + закрытое объектное хранилище (РФ) -> адаптеры CRM, БКИ, ЭП. 
Публичный калькулятор остаётся без регистрации. Закрытый кабинет использует серверную сессию. Подтверждение контакта не равнозначно идентификации личности. Для юридических лиц проверяются полномочия представителя. Реальная идентификация — через согласованный с партнёром сервис или процедуру.

## Контракты нашего API (проект, не адреса поставщиков)
| Метод | Путь | Результат |
|---|---|---|
| POST | /api/v1/session/challenge | Идентификатор проверки контакта, ограничение частоты |
| POST | /api/v1/session/verify | Серверная сессия после проверки кода |
| POST | /api/v1/identity/start | Идентификатор процесса идентификации |
| GET | /api/v1/identity/status | Статус идентификации |
| POST | /api/v1/applications | Идентификатор заявки, черновик |
| PATCH | /api/v1/applications/{id} | Изменение параметров с проверкой версии |
| GET | /api/v1/applications/{id} | Заявка и доступные действия |
| POST | /api/v1/applications/{id}/documents | Проверка доступа, загрузка в карантин |
| GET | /api/v1/applications/{id}/documents | Статусы проверки файлов |
| POST | /api/v1/applications/{id}/consents | Отдельное подтверждение версии документа |
| POST | /api/v1/applications/{id}/credit-requests | Только после идентификации и действительного отдельного согласия |
| GET | /api/v1/applications/{id}/credit-requests/{requestId} | Статус, без раскрытия лишних данных |
| GET | /api/v1/applications/{id}/offers | Реально полученные предложения |
| POST | /api/v1/applications/{id}/offers/{offerId}/select | Выбор предложения |
| POST | /api/v1/applications/{id}/signing | Запуск согласованной процедуры подписи |
| GET | /api/v1/contracts | Доступные клиенту договоры |
| POST | /api/v1/contracts/{id}/requests | Обращение по договору |

Все операции с объектами требуют проверки прав на конкретный объект; сервер не доверяет состоянию браузера. Повторные запросы БКИ и подписи — идемпотентные, с уникальным ключом. Не повторять платный запрос при неизвестном статусе. Сведения о БКИ и согласии не передаются лизингодателям автоматически без соответствующего законного основания. Не принимать решений об отказе исключительно по результатам автоматического анализа без надлежащих правовых оснований и процедуры.

## Адаптеры
- IdentityProvider: начать, проверить результат, получить подтверждение личности/полномочий.
- BureauProvider: проверить поддерживаемый способ согласия, создать запрос, получить состояние; сырой отчёт доступен только уполномоченным лицам.
- CrmProvider: создать заявку, обновить этап, получить предложения; не пересылать целиком кредитный отчёт по умолчанию.
- SignatureProvider: подготовить документ, начать подписание, проверить подпись и сохранить доказательства.
- DocumentStore: карантин, разрешённые форматы, проверка размера и сигнатуры, антивирус, приватный доступ, журнал, удаление по срокам.
- Неизвестный или отключённый адаптер возвращает 503; не подменять результат вымышленным ответом.

## Перед подключением
Получить у Тариэля название БКИ и описание действующего договора/разрешённых методов доступа, технические инструкции API или готового кабинета, название CRM, предпочтительный сервис идентификации и подписи. Секреты хранить только на сервере, не в репозитории, не в браузере, не присылать в обычный чат. Подтвердить оператора, адрес, сроки хранения, договоры с обработчиками, уведомление РКН, локализацию, основания и содержание отдельного согласия БКИ. Использовать версию согласия, время, идентификатор субъекта, получателя, цель, доказательство волеизъявления. До запуска провести проверку авторизации, загрузки файлов, XSS/CSRF, rate limits, отказоустойчивости, журналирования, восстановления и удаления данных.
